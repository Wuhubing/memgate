# 长时域 Memory 门控：项目与工程实现

Oct 26, 2026 · @wuhu

本项目在一个 LLM 固定不动的 agent harness 里，训练一个 memory 准入控制器：每一轮决定哪些 memory 进入模型输入，目标是整个 session 的累计回报。核心问题是这个决策能否当作 bandit，还是必须当作 MDP 做长期规划。

本标签页是项目文档（做什么、为什么、RL 在哪里）；代码怎么写见 工程实现文档。

## 背景

**Memory 在 harness 里是怎么工作的。** 现在的 agent harness 基本都配一个长期 memory，流程分三步：写入（把对话里的事实、偏好、进行中的任务存成记录）、检索（每一轮按当前请求做相似度检索，取前 k 条）、注入（把检索结果拼进 system prompt 或对话历史）。其中注入这一步通常是一个固定规则：取 top-k，或者相似度超过阈值就放。

**Memory 会帮倒忙。** 注入不是免费的，常见的副作用有三类：

- **过时信息误导**：memory 里存的是旧值（截止日期改了、负责人换了），但看起来和新值一样可信，模型会沿用旧值，甚至在用户纠正之后还会回到旧值。
- **无关信息打扰**：和当前问题无关的 memory 被放进来，模型会顺手提起，用户会觉得被打扰；而且同一件事被反复提起，打扰感会累积。
- **上下文成本**：注入的内容占 token；如果注入的内容留在对话历史里，之后每一轮都要为它付费。

已有研究也证实了这一点：不加选择地注入共享 memory 会降低表现，选择性使用可以把损失找回来（[SEDM](https://arxiv.org/abs/2509.09498)）；在编程 agent 里，错误的 memory 注入会让模型锚定在错误的修复思路上，并且这种污染会随 memory 规模增长（[Learning When to Remember](https://arxiv.org/abs/2604.27283)）。

**已有方法的空白。** 近期已有几篇工作学习"什么时候用 memory"：MemCon 用表格型上下文 bandit 加 UCB 选择 memory 操作（[MemCon](https://arxiv.org/abs/2607.13591)）；SEDM 的门控同时预测用与不用两种情况下的成功率；Learning When to Remember 用风险敏感的上下文 bandit，对错误注入罚得更重。它们的共同点是**把每次决策当成独立的 bandit**，只按当前这一轮的结果来评价。

但 session 有三个结构，bandit 看不到：

1. **本轮不可撤销**：memory 一旦写进对话历史，之后每一轮都在。
2. **影响会累积**：反复提及、锚定效应、token 成本都随轮次叠加。
3. **价值有时机**：同一条 memory 如果之后会被反复用到，早一点放进去可以复用；如果只是暂时相关，放进去反而会在之后的轮次里变成噪声。

这三点正是 MDP 和 bandit 的区别，也就是本项目要研究的问题。

## 研究问题与假设

核心问题：**memory 门控什么时候可以当 bandit 处理？忽略注入的持续影响，会损失多少？** 假设在做实验之前写定，每条对应一个可以否证的实验。

| 假设 | 内容 | 检验方式 |
| --- | --- | --- |
| H1 持续性 | 注入的过时或无关 memory 会影响之后的轮次：模型会再次提起它，或在用户纠正后仍使用旧值 | 预实验：测注入后第 1–5 轮的重复提及率和旧值使用率 |
| H2 时间跨度 | session 越长、过时和无关 memory 越多，短视策略和长期策略的差距越大 | 扫描 session 长度（4–20 轮）和过时比例（0–60%） |
| H3 机制 | 从状态里去掉注入历史后，长期策略的优势会退回到 bandit 水平 | 消融实验 |
| H4 持久性开关 | 如果注入是一次性的（每轮重新生成、不留在历史里），bandit 和长期策略的差距会明显缩小 | 同一套实验在两种注入模式下各跑一遍 |

H4 是最干净的一个对照：它直接关掉了"不可撤销"这个机制。如果差距确实来自持久性，关掉之后差距应该接近消失。如果关掉之后差距仍在，说明长期影响主要通过模型自己之前的回答传递（模型在第 3 轮提过的事，第 6 轮还在历史里），这本身也是一个有意思的发现。

## RL 在哪里参与

RL 学的是控制器的策略 π(a | s)；LLM、检索器和模拟用户都是环境，不训练。控制器不知道 LLM 会怎么反应，只能通过跑 session、拿奖励来学。

**MDP 定义**（一个 session 是一个 episode，有限时域 T = 8–15 轮）

| 要素 | 定义 |
| --- | --- |
| 状态 s\_t | 当前请求；前 3 条候选 memory 的特征（相似度、排名、新旧、类别、是否已被更新的记录取代）；**注入历史**（哪些已在上下文中、各被提及几次、注入了几轮）；当前轮次和剩余轮数 |
| 动作 a\_t | 从 3 条候选里选一个子集注入，共 8 种 |
| 转移 | 固定的 LLM 回答；注入的 memory 留在对话历史里；模拟用户发出下一个请求，可能是提问、闲聊，或更新某个事实 |
| 奖励 r\_t | 见下式 |
| 目标 | 最大化 session 回报 G = Σ γ^t r\_t |

```latex
r_t = \mathbb{1}[\text{答对}] - \delta\,\mathbb{1}[\text{用了旧值}] - \alpha \sum_{m \in \text{无关提及}} \beta^{\,n_m} - \lambda \cdot \text{上下文中的 memory token 数}
```

n\_m 是 memory m 之前被提及的次数（β > 1，提得越多扣得越重）。最后一项按当前上下文里全部 memory 计费，所以第 t 轮注入的一条 memory，会在剩下的 T − t 轮里每轮都付费。

**为什么不是监督学习。** 监督学习需要每一轮都有"应该注入什么"的标签，但这个标签不存在：第 3 轮放一条 memory 是好是坏，取决于第 4 到第 T 轮发生什么；同一条 memory，之前放过和没放过，最优选择也不同。奖励延迟、依赖历史，这是长期 credit assignment，正是课程要求的"RL 的必要性"。

**为什么不是 bandit。** 令 γ = 0，上面的 MDP 就退化成上下文 bandit。下图是两者评价范围的区别。

bandit 只按第 2 轮的结果判断这次注入；MDP 把之后每轮的 token 成本、重复打扰和复用收益都算进来。

**RL 在三个层面参与。**

1. **基于模型的规划（DP）**：从真实 LLM 日志拟合一个行为模型 P̂，在小规模实例上用倒推法精确求解最优 Q\*。同一个模型上只看一步的贪心策略，就是"没有学习误差的 bandit"。两者的价值之差，就是纯粹的短视损失。
2. **无模型学习**：DQN 和 PPO 在模拟器上训练，γ 取 0、0.5、0.9、1。状态里有剩余轮数，所以有限时域下 γ = 1 也是合法的。同一套网络只改 γ，是最干净的 bandit 与 MDP 对照。
3. **探索**：LinUCB 作为 bandit baseline，DQN 用 ε-greedy，PPO 用熵正则。

倒推法用的是有限时域的 Bellman 方程：

```latex
Q_t(s, a) = \hat{r}(s, a) + \gamma \sum_{s'} \hat{P}(s' \mid s, a)\, \max_{a'} Q_{t+1}(s', a'), \qquad Q_{T}(\cdot) = 0
```

短视损失定义为 Δ = V^{DP} − V^{greedy}，它是本项目最核心的量。

## 方法与对比

所有方法共用同一个环境和同一套状态特征，只在"怎么做决策"上不同。分成三组：启发式 baseline、短视（bandit）方法、长期（MDP）方法。

| 方法 | 类别 | 作用 | 对应课程内容 |
| --- | --- | --- | --- |
| 全部注入 / 从不注入 | baseline | 两个极端 | — |
| 相似度阈值（阈值在验证集上调优） | baseline | 现在 harness 的常见做法 | 启发式策略 |
| LinUCB（对 8 个联合动作） | 短视 | 代表 MemCon 一类已有方法 | 探索与利用、上下文 bandit |
| 风险敏感 bandit（错误注入加倍惩罚） | 短视 | 代表 Learning When to Remember | 奖励设计 |
| 模型上的贪心一步策略 | 短视 | 没有学习误差的 bandit，分离出短视损失 | 一步前瞻（one-step lookahead） |
| DQN，γ = 0 | 短视 | 和下一行同网络、同数据，只差 γ | Q-learning、函数近似 |
| DQN，γ ∈ {0.5, 0.9, 1} | 长期 | 主方法之一 | Q-learning、经验回放、target network |
| PPO | 长期 | 策略梯度对照 | 策略梯度、GAE |
| DQN 去掉注入历史 | 长期（消融） | 检验 H3 | 状态设计与部分可观测 |
| 小实例上的倒推 DP 最优 | 长期（上界） | 衡量学习策略离最优有多远 | 有限时域 DP、Bellman 方程 |

这个设计把最终的差距拆成两部分：**短视损失**（DP 最优减贪心一步，两者用同一个模型，没有学习误差）和**学习损失**（学出来的策略减对应的模型最优）。报告里会分别报告这两部分。

## 实验设计与评价指标

实验按顺序进行，第 1 个是去留判断：如果预实验里模型几乎不受 memory 影响，就先调整环境，再做后面的。

1. **E0 预实验（H1）**：50 个 session，四种条件（不注入、注入正确、注入过时、注入无关）。测量注入后第 1–5 轮的重复提及率、用户纠正后的旧值使用率。**继续的条件**：无关 memory 在后续轮次的重复提及率 ≥ 10%，或纠正后旧值使用率 ≥ 10%。
2. **E1 主对比**：默认设置（12 轮、30% 过时、40% 无关候选，持久注入模式）下所有方法。
3. **E2 γ 扫描**：同一个 DQN，γ 取 0、0.3、0.6、0.9、1，画回报随 γ 的曲线。
4. **E3 差距曲线（H2）**：短视损失随 session 长度和过时比例（0–60%）的变化：小实例上用 DP 与贪心精确计算 Δ（4–10 轮），完整规模上用 DQN γ = 0.9 与 γ = 0 的差近似（4–20 轮）。
5. **E4 消融（H3）**：去掉注入历史特征后重训。
6. **E5 持久性开关（H4）**：E1 和 E3 在"一次性注入"模式下重跑。
7. **E6 模拟到真实**：所有策略在真实 LLM 上各跑 300 个 session，和模拟器结果比较排序。
8. **E7（可选）换模型**：用一个更强的 LLM 重复 E0 和 E6，看锚定效应和最优门控是否随模型能力变化。

**评价指标**

| 指标 | 定义 |
| --- | --- |
| session 回报 | 主指标，均值 ± 95% 置信区间（按 session bootstrap） |
| 答对率 | 提问轮里答对当前值的比例 |
| 旧值错误率 | 提问轮里用了过时值的比例 |
| 打扰次数 | 每个 session 里无关提及的次数 |
| memory token | 每轮平均在上下文里的 memory token 数 |
| 短视损失 Δ | V^{DP} − V^{greedy}，只在可求解的小实例上 |
| 排序一致性 | 模拟器和真实 LLM 上各方法排名的 Spearman 相关系数 |

所有学习方法跑 5 个随机种子；各方法在同一组测试 session 上评估，用配对差值做比较。

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| 预实验发现模型几乎不受过时或无关 memory 影响 | 换更小的模型、把 system prompt 改得更鼓励使用 memory、让过时信息更隐蔽；"模型很稳健"本身也是可报告的结论。即使 LLM 行为效应很弱，token 成本和复用这两个机制仍然产生长期结构 |
| bandit 和长期策略没有差距 | 如实报告并解释原因（即 bandit 简化合理），课程明确接受有解释的负面结果 |
| 拟合的模拟器和真实 LLM 行为不一致 | 所有结论用真实 LLM 验证（E6），报告排序一致性；不一致的地方本身作为局限性讨论 |
| DQN 在小样本下不稳定 | 动作空间只有 8 个、状态约 40 维，模拟器上可以跑几十万步；5 个种子取平均 |
| DP 状态空间太大 | 只在抽象后的小实例上求精确解（memory 池 ≤ 6 条、T ≤ 10、提及次数截断到 2） |
| 合成环境被认为太玩具 | 有余力时在公开的多 session memory 基准 LongMemEval 上做一组回放验证 |
| API 模型版本变化、输出不确定 | 固定带日期的模型版本，或用开源模型自部署；多种子、报告置信区间 |
| 时间花在搭环境上 | harness 保持在约 300–500 行；第 2 周结束前必须在模拟器上跑出第一版 γ 扫描 |
