# 工程实现文档

代码库叫 memgate，纯 Python。核心原则：真实 LLM 只用来收集日志和最终验证，所有 RL 训练和参数扫描都在拟合的模拟器上跑，同一个 Gymnasium 环境可以切换两种后端。

## 总览

整个工程是一条流水线：生成合成会话，在真实 LLM 上用随机策略收集日志，拟合行为模型得到模拟器，在模拟器上做全部规划和训练，最后回到真实 LLM 验证。

&#91;embedded content: 实验流水线 · 7 个阶段\]

这样分工的原因是成本和速度：一次 DQN 训练要几十万步，在模拟器上只需几分钟，在真实 LLM 上则要几十万次模型调用。真实 LLM 的两个阶段加上预实验约 5,600 个 session。

## 技术选型

原则是能用现成的就不自己写；自己写的只有生成器、harness 主循环、打分器、环境和 DP。

| 用途 | 选择 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.11 | 类型标注 + dataclass |
| LLM 调用 | openai SDK（异步客户端） | 只用 OpenAI 兼容接口，同一份代码可连托管 API 或自部署的 vLLM |
| 自部署模型（可选） | vLLM + Qwen3-8B（关闭 thinking） | 开启 prefix caching，同一 session 的历史可复用 |
| 检索 | sentence-transformers（all-MiniLM-L6-v2）+ rank\_bm25 | 两路结果用 reciprocal rank fusion 合并 |
| RL 环境接口 | gymnasium | 课程推荐，可直接接 SB3 |
| RL 算法 | stable-baselines3（DQN、PPO） | LinUCB 和 DP 自己写，各约 100 行 |
| 行为模型 | scikit-learn（LogisticRegression） | 小、可解释、拟合快 |
| 日志与数据 | pandas + parquet | 每轮一行，便于拟合和分析 |
| 配置 | YAML + pydantic 校验 | 每个实验一个配置文件，结果目录里保存配置副本 |
| 实验记录 | TensorBoard（SB3 自带） | 可选 wandb |
| 作图 | matplotlib | 报告用图统一脚本生成 |
| 测试 | pytest | 重点测打分器和 DP |

**为什么不用 LangGraph、Letta、Mem0 整套框架**：它们把检索封装在 prompt 组装里，拦截"每轮放什么"需要改内部代码；也没法从同一个状态分叉出"注入"和"不注入"两条路径。我们只借用 Mem0 的记录格式，主循环自己写。

## 数据结构

所有模块之间只传这几个对象。关键设计：每条 memory 的 value 是全局唯一的字符串，所以打分只靠字符串匹配；每轮的标注在生成时就写好。

```python
from dataclasses import dataclass, field
from typing import Literal

Category = Literal["preference", "project", "schedule", "contact", "trivia"]

@dataclass(frozen=True)
class MemoryRecord:
    id: str                  # "u03-m17"
    user_id: str
    key: str                 # 同一事实的不同版本共享 key，如 "kestrel.deadline"
    value: str               # 在整个世界里唯一，如 "Halcyon Room"、"Friday 14 November"
    text: str                # 注入时的自然语言句子
    category: Category
    created_at: int          # 虚拟时间戳（天）
    superseded_by: str | None = None   # 被更新的记录取代时指向新记录（控制器不可见）
    tokens: int = 0

@dataclass(frozen=True)
class Turn:
    idx: int
    kind: Literal["query", "chat", "update"]
    text: str                         # 用户说的话
    target_key: str | None            # query / update 涉及的事实
    answer_value: str | None          # query 的正确当前值
    stale_values: tuple[str, ...]     # 该 key 的全部过时值
    relevant_ids: frozenset[str]      # 本轮真正需要的 memory
    new_record: MemoryRecord | None   # update 轮写入的新记录

@dataclass(frozen=True)
class SessionScript:
    id: str
    user_id: str
    turns: tuple[Turn, ...]

@dataclass
class SessionState:                  # 环境内部状态，可以 copy.deepcopy 用来分叉
    script: SessionScript
    t: int = 0
    store: list[MemoryRecord] = field(default_factory=list)
    in_context: dict[str, int] = field(default_factory=dict)     # memory id -> 注入轮次
    mentions: dict[str, int] = field(default_factory=dict)       # memory id -> 被提及次数
    messages: list[dict] = field(default_factory=list)           # 对话历史（live 后端用）
    conflict_flag: bool = False                                  # 上一轮是否出现过旧值与纠正冲突

@dataclass
class TurnLog:                       # 日志每轮一行，写入 parquet
    session_id: str; t: int; kind: str
    candidate_ids: list[str]; candidate_feats: list[list[float]]
    action: int; injected_ids: list[str]
    prompt_tokens: int; completion_tokens: int
    response: str
    correct: bool; stale_used: bool
    intrusion_ids: list[str]
    r_quality: float; r_stale: float; r_intrusion: float; r_tokens: float; reward: float
    policy: str; mode: Literal["persistent", "ephemeral"]; seed: int
```

## 模块 1：世界与 session 生成器

生成器产出三样东西：虚构用户、每个用户的 memory store、带标注的 session 脚本。对话内容用英文（LLM 在英文下行为更稳定），全部实体都是虚构的，避免模型用自己的知识作答。

**事实的三种类型**（每个用户默认 14 个 key）

| 类型 | 数量 | 例子 | 作用 |
| --- | --- | --- | --- |
| 会变的事实 | 6 | Project Kestrel 的截止日、周会所在会议室、对接人 | 每个有 1–3 个历史版本，只有最新的是对的；产生过时信息 |
| 稳定偏好 | 4 | 喜欢的写作风格、常用工具 | 只有一个版本，有时会被问到 |
| 无关琐事 | 4 | 宠物的名字、常去的咖啡馆 | 从不被问，但会被检索到；纯干扰项 |

每个用户的 store 大约 30–45 条记录。过时比例由会变事实的历史版本数控制，是实验 E3 的扫描参数。

**Session 脚本**：长度 T（默认 12），每轮独立抽取类型：

- **提问（40%）**：问某个会变事实或偏好的当前值。key 按 Zipf 分布抽，保证同一个 key 在一个 session 里经常被问 2–3 次，产生"复用"的价值。
- **闲聊或一般任务（45%）**：如"帮我改一下这段话"，不需要任何 memory。其中一半的句子会提到和 memory 同一主题的词（"帮我给 Kestrel 团队写个开场白"），让检索器给出看起来相关、实际无关的候选。
- **更新（15%）**：用户说某个会变事实变了（"Kestrel 的截止日推到了 Friday 5 December"）。harness 用固定的写入规则把新记录加进 store，旧记录从此过时。之前已经注入到上下文里的旧值就变成了污染源。

```python
def make_session(user, rng, T, p=(0.40, 0.45, 0.15)):
    store = list(user.initial_store)
    turns = []
    for t in range(T):
        kind = rng.choice(["query", "chat", "update"], p=p)
        if kind == "query":
            key = zipf_pick(user.queryable_keys, rng)
            cur = current_record(store, key)
            turns.append(Turn(t, "query", fill(QUERY_TPL, key), key, cur.value,
                              stale_values(store, key), frozenset({cur.id}), None))
        elif kind == "chat":
            topic = rng.choice(user.keys) if rng.random() < 0.5 else None
            turns.append(Turn(t, "chat", fill(CHAT_TPL, topic), None, None, (), frozenset(), None))
        else:
            key = rng.choice(user.changing_keys)
            new = new_version(store, key, rng)      # 从词表取一个未用过的值
            store = supersede(store, key, new)
            turns.append(Turn(t, "update", fill(UPDATE_TPL, key, new.value), key, None, (), frozenset(), new))
    return SessionScript(new_id(), user.id, tuple(turns))
```

**数据划分**：用户按 60 / 20 / 20 分成训练、验证、测试，互不重叠。日志收集和模拟器训练只用训练用户；阈值和超参在验证用户上调；所有报告数字来自测试用户。生成器完全由 seed 决定，同一个 seed 生成完全相同的世界。

## 模块 2：检索器

检索器固定不学习，模仿常见 harness 的做法：用当前用户输入做查询，BM25 和 embedding 各排一次序，用 reciprocal rank fusion 合并，返回前 3 条。

- **不过滤过时记录**：和大多数真实 harness 一样，旧版本和新版本都可能被检索到，而且旧版本经常排在前面（它们和问句的词重合度一样高）。这是过时信息进入候选的主要来源。
- **持久模式下排除已在上下文中的记录**：已经注入过的不再作为候选，否则重复注入没有意义。一次性模式下每轮都从全部 store 里检索。
- **不足 3 条时用空位补齐**，空位的特征全为 0，对应的注入动作无效。
- **缓存**：embedding 在生成世界时一次算好存盘；训练时检索只是一次矩阵乘法，不影响模拟器速度。

接口：

```python
class Retriever:
    def __init__(self, store_embeddings, bm25_index, k=3): ...
    def topk(self, query: str, store: list[MemoryRecord], exclude: set[str]) -> list[Candidate]:
        """返回长度固定为 k 的列表，每个 Candidate 含 record、cos 相似度、bm25 分、融合后排名"""
```

## 模块 3：harness 与 LLM 调用

harness 做的事很少：拼消息、调模型、把回答交给打分器。唯一的设计点是**两种注入模式**，它们是假设 H4 的实验开关。

**System prompt（两种模式共用）**

```
You are a helpful personal assistant. Notes about the user may appear inside
<memory> tags. Use a note only if it is relevant to the user's current request.
Answer in at most 80 words.
```

限制回答长度有两个好处：省 token，以及让打分更稳定。预实验里会另外试一个不加"只在相关时使用"这句的版本，用来调节锚定效应的强弱。

**持久模式**（默认）：注入内容拼在当前用户消息前面，作为这条消息的一部分留在历史里。用 user 消息而不是中途插入 system 消息，是因为不少 API 不支持多条 system 消息。

```python
[
  {"role": "system", "content": SYSTEM},
  {"role": "user", "content": "<memory>\n- Project Kestrel's deadline is Friday 14 November.\n</memory>\n\nWhen is Kestrel due again?"},
  {"role": "assistant", "content": "..."},
  {"role": "user", "content": "Can you tighten this paragraph for me? ..."},   # 本轮不注入，但上一条的 <memory> 还在
]
```

**一次性模式**：历史里只保留原始用户消息；本轮的 memory 只加在 system prompt 末尾，下一轮重新生成。这样注入内容本身不累积，但模型之前的回答里提到的东西仍然会留在历史里。

**调用参数**：temperature 0.7、top\_p 0.95、max\_tokens 160；Qwen3 关闭 thinking。保留温度是为了让同一状态下的结果有随机性，模拟器拟合的是概率而不是确定结果。

**Runner**

- 每个 session 内部是顺序的（下一轮依赖上一轮的回答），session 之间用 asyncio 并发，信号量默认 32。
- 失败重试：指数退避加随机抖动，最多 5 次；仍失败的 session 整个丢弃并记录，不要写半个 session。
- 响应缓存：以 hash(模型名, messages, seed) 为 key 存在本地 SQLite，重跑脚本不重复付费。
- 每轮写一行 TurnLog，每 100 个 session flush 一次 parquet。

```python
async def run_session(script, policy, llm, retriever, scorer, mode, seed) -> list[TurnLog]:
    st = SessionState(script, store=list(initial_store(script.user_id)))
    logs = []
    for turn in script.turns:
        cands = retriever.topk(turn.text, st.store, exclude=set(st.in_context) if mode == "persistent" else set())
        obs = featurize(st, cands, turn)
        a = policy.act(obs)
        chosen = [c for i, c in enumerate(cands) if a >> i & 1 and c is not None]
        msgs = build_messages(st, turn, chosen, mode)
        resp = await llm.chat(msgs, seed=seed)
        out = scorer.score(st, turn, chosen, resp.text, mode)
        st = advance(st, turn, chosen, resp.text, out)   # 更新 in_context、mentions、store、messages
        logs.append(make_log(st, turn, cands, a, chosen, resp, out))
    return logs
```

## 模块 4：打分器

打分器把一条回答变成奖励的四个分项，只用字符串匹配，不调 LLM。前提是生成器给每个 value 配了别名表（如 "Friday 14 November" 的别名有 "14 November"、"Nov 14"），并保证不同 value 的别名互不重叠。

**匹配规则**：回答和别名都转小写、去标点、合并空白，然后做子串匹配。

| 判定 | 条件 | 适用轮次 |
| --- | --- | --- |
| 答对 | 当前值的任一别名出现在回答里 | 提问 |
| 用了旧值 | 某个过时值出现，且当前值没出现（"原来是 X，现在是 Y"算答对） | 提问 |
| 无关提及 | 某条 memory 的 value 出现，但它不在本轮 relevant\_ids 里，且不属于本轮的 target\_key | 全部 |
| 提及计数 | 每次无关提及给该 memory 的 n\_m 加 1，用于下次惩罚的指数 | 全部 |

```python
def score(st, turn, chosen, response, mode, cfg):
    resp = normalize(response)
    hit = lambda v: any(a in resp for a in aliases(v))
    r_quality = r_stale = 0.0
    if turn.kind == "query":
        cur = hit(turn.answer_value)
        r_quality = 1.0 if cur else 0.0
        r_stale = -cfg.delta if (not cur and any(hit(v) for v in turn.stale_values)) else 0.0
    intrusions = [m for m in st.store
                  if m.id not in turn.relevant_ids and m.key != turn.target_key and hit(m.value)]
    r_intr = -cfg.alpha * sum(cfg.beta ** st.mentions.get(m.id, 0) for m in intrusions)
    ctx = st.in_context.keys() | {c.id for c in chosen} if mode == "persistent" else {c.id for c in chosen}
    r_tok = -cfg.lam * sum(tokens(i) for i in ctx)
    return Outcome(r_quality, r_stale, r_intr, r_tok, intrusions)
```

**默认系数**（reward.yaml）：δ = 1.0，α = 0.3，β = 1.5，λ = 0.002 / token。一条约 25 token 的 memory 在上下文里留 10 轮，累计成本约 0.5，和一次答对的收益是同一个量级，这样三种权衡都真实存在。报告附录里对 α 和 λ 各做一组敏感性分析。

**打分器的验证**：预实验结束后人工标注 200 条回答，要求答对与旧值判定的一致率 ≥ 95%、无关提及 ≥ 90%。达不到就补别名表，或收紧 system prompt 里的回答格式。

## 模块 5：Gymnasium 环境

`MemGateEnv` 是所有策略共用的接口。一个 episode 就是一个 session，一步就是一轮；后端在构造时指定为 `live` 或 `sim`，对策略完全透明。

**动作**：`Discrete(8)`，把动作编号看成 3 位二进制掩码，第 i 位为 1 表示注入第 i 个候选。空位对应的位被忽略。DQN 和 PPO 用同一个动作空间，结果可以直接比较。

**观测**：50 维向量，每个候选位 14 维 × 3，加 8 维全局特征。观测只用 harness 在真实部署中也能拿到的信息，不用任何生成器标注（如 relevant\_ids、superseded\_by）。标「历史」的特征在 H3 消融实验里置零。

| 特征 | 维度 | 来源 | 历史 |
| --- | --- | --- | --- |
| 位是否有效 | 1 × 3 | 检索器 |  |
| 余弦相似度、归一化 BM25 分、融合排名 | 3 × 3 | 检索器 |  |
| 记录年龄（天，归一化）、token 数 | 2 × 3 | 记录元数据 |  |
| 类别 one-hot | 5 × 3 | 记录元数据 |  |
| 候选中有同 key 的更新版本 | 1 × 3 | 检索器 + 时间戳 |  |
| 同 key 的其他版本已在上下文中 | 1 × 3 | 注入历史 | 是 |
| 本 session 内此前作为候选出现的次数 | 1 × 3 | 注入历史 | 是 |
| 当前轮次 t/T、剩余轮数 (T−t)/T | 2 | 计数器 |  |
| 上下文中的 memory 条数、memory token 总数 | 2 | 注入历史 | 是 |
| 上一个回答里提到的上下文 memory 数、单条最大被提及次数 | 2 | 回答文本匹配 | 是 |
| 上下文中已被更新记录取代的 memory 条数、上一轮是否有更新与上下文冲突 | 2 | 注入历史 + 写入日志 | 是 |

剩余轮数在状态里，所以有限时域下可以直接用 γ = 1，策略仍然是马尔可夫的。

```python
class MemGateEnv(gym.Env):
    def __init__(self, scripts, backend, retriever, mode="persistent", mask_history=False, seed=0):
        self.action_space = gym.spaces.Discrete(8)
        self.observation_space = gym.spaces.Box(-1.0, 1.0, shape=(50,), dtype=np.float32)

    def reset(self, *, seed=None, options=None):
        self.st = SessionState(self.rng.choice(self.scripts), ...)
        self.cands = self._retrieve()
        return self._obs(), {}

    def step(self, action):
        turn = self.st.script.turns[self.st.t]
        chosen = [c for i, c in enumerate(self.cands) if (action >> i) & 1 and c is not None]
        out = self.backend.step(self.st, turn, chosen, self.mode)   # live: 调 LLM 再打分；sim: 直接采样结果
        self.st = advance(self.st, turn, chosen, out)
        done = self.st.t == len(self.st.script.turns)
        self.cands = [] if done else self._retrieve()
        return self._obs(), out.reward, done, False, {"outcome": out}

    def fork(self):                       # 给 DP 验证和反事实分析用
        return copy.deepcopy(self)
```

live 后端是异步的，在环境里用一个同步包装；批量评估时不走 env，直接用 runner 并发跑。

## 模块 6：行为模型与模拟器

模拟器不生成文字，只生成打分器需要的结果：答对、用了旧值、哪些 memory 被提及。这些结果的概率从真实 LLM 的日志里拟合。

**收集日志**：只用训练用户。行为策略是混合的：70% 的 session 每轮均匀随机选动作（覆盖各种状态），30% 用阈值策略（覆盖真实使用中常见的状态）。每种注入模式各 1,500 个 session，共约 36,000 轮。

**三个子模型**（都是 scikit-learn 的逻辑回归，带 L2 正则）

| 子模型 | 预测什么 | 主要特征 |
| --- | --- | --- |
| 回答结果（三分类） | 提问轮：答对 / 用了旧值 / 都没有 | 当前版本是否在上下文、上下文里同 key 的过时版本数、用户是否在本 session 里说过新值、当前版本与过时版本各自注入了几轮、上下文 memory 总数、注入模式 |
| 提及（二分类，每条 memory 一样本） | 某条无关 memory 是否在本轮回答里被提到 | 是否本轮刚注入、注入后经过的轮数、之前被提及次数 n\_m、与本轮输入的相似度、本轮类型、类别、上下文 memory 总数 |
| 回答长度 | 生成 token 数（线性回归） | 只用来估算成本，不进入奖励 |

提及模型的样本包括两类 memory：当前在上下文中的，以及不在上下文但之前被模型提到过的（一次性模式下，影响通过模型自己的旧回答传递）。

**采样**：每轮先从三分类模型抽回答结果，再对每条候选 memory 独立抽一次是否被提及，然后走和 live 后端完全相同的打分与状态更新代码。单步耗时在微秒级，一次 30 万步的 DQN 训练几分钟内完成。

**模拟器本身的验证**（不过不进入训练阶段）

1. 留出 20% 的日志 session，看各子模型的对数似然和校准曲线。
2. 用同一个行为策略在模拟器上重跑，比较 session 回报各分项的分布和真实日志是否一致。
3. 对照一个梯度提升树版本；如果它明显更准，就说明逻辑回归漏掉了重要的交互项，需要补特征。

## 模块 7：DP 与贪心规划

完整规模的状态太大，精确 DP 只在抽象出来的小实例上做。小实例用同一个行为模型的概率，所以 DP 和贪心的差距就是纯粹的短视损失。

**小实例的定义**

- memory 池 5 条：两个会变的 key A、B，各有当前值和一个过时值；再加一条无关琐事。
- 每轮请求从 6 种类型里独立抽：问 A、问 B、与 A 主题相关的闲聊、无关闲聊、更新 A、更新 B。
- 检索器替换成固定规则：每种请求类型对应固定的 3 个候选（问 A 时是 A 当前、A 过时、琐事）。
- 状态 = (t, 每条记录是否在上下文, 每条记录被提及次数截断到 0/1/2, A 和 B 是否在本 session 里被更新过)。最多 10 × 2^5 × 3^5 × 4 ≈ 31 万个状态，实际可达的远少于此。
- T 取 4 到 10，对应实验 E3 的横轴。

控制器先看到本轮请求再做决定，所以值函数先对请求类型取期望，再对动作取最大：

```latex
V_t(s) = \sum_{k} p(k)\, \max_{a} Q_t(s, k, a), \qquad Q_t(s, k, a) = \sum_{o} \hat{P}(o \mid s, k, a)\, \big[ r(s, k, a, o) + \gamma V_{t+1}(f(s, k, a, o)) \big]
```

这里 o 是一轮的结果（回答类别加被提及的 memory 子集），f 是确定性的状态更新。提及事件在给定状态下按独立处理，所以结果数最多是 3 × 2^5 = 96。

```python
@functools.lru_cache(maxsize=None)
def V(s: AbsState) -> float:
    if s.t == T:
        return 0.0
    return sum(p_kind[k] * max(Q(s, k, a) for a in range(8)) for k in KINDS)

def Q(s, k, a) -> float:
    return sum(p * (r + GAMMA * V(nxt)) for p, r, nxt in outcomes(s, k, a))   # outcomes 用 BehaviorModel.probs

def greedy_action(s, k) -> int:
    return max(range(8), key=lambda a: sum(p * r for p, r, _ in outcomes(s, k, a)))
```

**评估方式**：DP 策略和贪心策略的价值都用同一个递归精确计算（策略评估），不靠采样，所以 Δ = V^{DP} − V^{greedy} 没有噪声。学出来的策略在同一个小实例上用 2 万个采样 session 估计价值。

**注意信息不对等**：DP 和贪心知道哪条记录是过时的，学习策略只看得到可观测特征。所以学习策略与 DP 的差距里，既有学习误差，也有部分可观测带来的损失。报告里分开说明，短视损失 Δ 的结论只用 DP 与贪心的对比。

## 模块 8：策略与训练

所有策略实现同一个接口 `act(obs) -> int`，评估脚本不区分策略类型。

**启发式**

- always：动作 7（三条全放）；never：动作 0。
- threshold：融合相似度超过 τ 的候选全放。τ 在验证用户上按 session 回报网格搜索，每种注入模式单独调。

**LinUCB**：对 8 个联合动作各维护一组线性模型，特征就是 50 维观测；奖励用当轮的 r\_t。探索系数 α\_UCB 在 {0.1, 0.5, 1.0} 里选。风险敏感版本把当轮的旧值和无关提及惩罚乘 2 后再用于更新。

**DQN（stable-baselines3）**

| 参数 | 取值 |
| --- | --- |
| 网络 | MLP \[128, 128\]，ReLU |
| 学习率 | 3e-4 |
| 经验回放 | 100,000 |
| batch size | 256 |
| target network 更新 | 每 1,000 步 |
| ε | 1.0 线性降到 0.05，用当全部步数的 30% |
| 总步数 | 300,000（约 25,000 个 session） |
| γ | 0、0.3、0.6、0.9、1.0 |
| 种子 | 5 个 |

**PPO（stable-baselines3）**：同样的网络结构，n\_steps 2,048、batch 256、GAE λ 0.95、熵系数 0.01，γ 取 0.9 和 1.0，其余用默认值。

**消融版本**：同一个 DQN 配置，只是 `mask_history=True`，把「历史」特征置零。

**超参调优的界限**：只在 γ = 0.9 上对学习率和网络宽度做一次小网格搜索，其他 γ 直接沿用。这样 γ 之间的差异不会被调参力度不同所混淆。

```python
# scripts/train.py 的核心
env = make_vec_env(lambda: MemGateEnv(train_scripts, SimBackend(bm), retriever,
                                      mode=cfg.mode, mask_history=cfg.mask_history), n_envs=8)
```

## 测试与正确性检查

最容易出错而且出错后最难发现的，是打分器和状态更新。下面的检查全部写成 pytest，每次改代码都跑。

**单元测试**

- 生成器：同一 seed 生成的世界完全一致；任意两个 value 的别名不重叠；每个提问轮的 answer\_value 等于该时刻 store 里该 key 最新的记录。
- 打分器：用手写的 30 条回答覆盖全部分支（答对、只用旧值、新旧都提、无关提及、大小写和标点变化）。
- 状态更新：持久模式下注入后 in\_context 只增不减；一次性模式下每轮清空；update 轮之后旧记录被标记为取代。
- 环境：观测向量在 \[−1, 1\] 内；`mask_history=True` 时历史特征确实为 0；空位对应的动作位不产生注入。
- live 与 sim 后端：对同一组给定的结果，两个后端的打分和状态更新完全相同（共用一份代码，测试保证不被改分叉）。

**理论上必须成立的关系**（不成立就说明有 bug）

| 检查 | 为什么必须成立 |
| --- | --- |
| V^{DP} ≥ V^{greedy}，且 ≥ 任何启发式在小实例上的精确价值 | DP 是最优的 |
| T = 1 时 V^{DP} = V^{greedy} | 只有一步时短视就是最优 |
| λ = α = δ = 0 且提及概率与历史无关时，Δ = 0 | 没有任何跨轮影响，MDP 退化为 bandit |
| 小实例上长时间训练的 DQN（γ = 0）接近贪心；γ = 1 接近 DP | 学习算法本身没问题 |
| 采样估计的策略价值与递归精确值相差在置信区间内 | 模拟器采样与 DP 的概率一致 |

第三和第四条是整个项目最重要的健全性检查，第 2 周就要跑通。

## 算力与成本估算

真实 LLM 的调用量大约是 5,600 个 session、6.7 万轮，其余都是 CPU 工作。

| 阶段 | session 数 | 约合输入 token | 说明 |
| --- | --- | --- | --- |
| E0 预实验 | 200 | 2.4M | 4 种条件 × 50 |
| 收集日志 | 3,000 | 36M | 两种注入模式各 1,500 |
| E6 真实评估 | 2,400 | 29M | 8 种方法 × 300 |
| 合计 | 5,600 | 约 67M | 输出约 6M token |

估算依据：每轮对话历史增长约 150 token（12 轮时提示约 1,900 token），整个 session 平均每轮约 1,000 输入 token、100 输出 token。同一 session 的历史是共同前缀，开启前缀缓存后大部分输入不需要重新计算。

**两种跑法**

- **自部署**：一张 40–80GB 显存的 GPU，vLLM + Qwen3-8B，开启 prefix caching。全部真实调用预计在几个 GPU 小时内完成，具体速度在 E0 时实测。
- **托管 API**：选一个便宜的小模型，固定带日期的版本。费用按"约 67M 输入 + 6M 输出，扣除缓存命中折扣"用当时的价格表算；注意速率限制，并发数从 8 开始。

**CPU 部分**：模拟器上大约 60 个训练 run（γ 扫描 25 个、其他方法和消融、一次性模式），每个 30 万步，在一台 8 核机器上并行跑，一天以内完成。DP 小实例每个参数组合在分钟级。数据量不到 1GB。
